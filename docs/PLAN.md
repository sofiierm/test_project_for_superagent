# План реализации

Как ТЗ превратилось в работающий сервис: этапы, решения и порядок проверки.
Служит картой кода: по разделу можно найти, где что лежит.

## Этап 0. Расчистка

Удалён мебельный лендинг целиком: исходники, сборка, шрифты, тесты, воркфлоу под
старый стек. Репозиторий начинается с чистого листа, чтобы не тащить мёртвый код
и не поддерживать два продукта одновременно.

Проверка: в дереве нет файлов старого сайта, `git status` чистый после коммита.

## Этап 1. Каркас и хранилище

`package.json` без runtime-зависимостей, `src/config.mjs` с конфигурацией из
окружения, `src/db/` — схема и репозитории поверх `node:sqlite`.

Схема: `accounts`, `videos`, `metric_snapshots`, `sync_runs`. Внешние ключи с
каскадным удалением, уникальность `(account_id, external_id)` — она же защита от
дубликатов при синхронизации.

Ключевое решение: **преобразование имён полей ровно на границе базы**. SQLite
отдаёт `snake_case`, весь остальной код работает с `camelCase`. Пока
преобразование было размазано, графики молча показывали нули; теперь это одна
функция на таблицу, и её проверяют интеграционные тесты.

## Этап 2. Разбор ввода и источники данных

`src/lib/account-url.mjs` — принимает ссылки и ники, различает профиль, пост и
видео, декодирует проценты (иначе `@ТихийВлог` не разбирался) и допускает
кириллицу в никах.

`src/providers/` — два провайдера за одним интерфейсом: детерминированный `demo`
и `ytdlp` для реальных данных. Классификация ошибок (`ytdlp_missing`, `timeout`,
`bot_check`, `rate_limited`, `not_found`) отделяет «нет сети» от «аккаунт
закрыт», чтобы интерфейс мог объяснить причину.

Решение: **демо-режим — режим по умолчанию в среде без доступа к платформам**, но
он всегда подписан как демонстрационный. Честная деградация важнее красивого
экрана с выдуманными цифрами.

## Этап 3. Анализ

- `src/analysis/metrics.mjs` — ER, медианы, квартили, ряды, сравнение периодов,
  лучшее время, выбросы, ритм.
- `src/analysis/text.mjs` — темы, хештеги, приёмы подачи, тональность.
- `src/analysis/insights.mjs` — правила формулировки выводов.

Отдельно решено: **ритм публикаций считается только внутри одного аккаунта**.
На обзоре ролики трёх аккаунтов смешивались, и сервис бодро советовал «раз в
день», хотя это был ритм трёх разных людей.

Приёмы подачи распознаются по основам слов, а не подстрокой: иначе
«лайкозависимость» считалась призывом «лайк».

Ориентиры ER по платформам (4 / 2,5 / 5 %) вынесены в `ER_BENCHMARKS` и
подписаны в ТЗ как середина отраслевых диапазонов, а не как официальные данные
платформ: это грубая система координат, и пользователь может подставить свои
цифры.

## Этап 4. Интерфейс

Серверная отрисовка через шаблонный тег `html` с автоматическим экранированием.
Никакого клиентского фреймворка: страница полезна без JavaScript, клиентский
скрипт только для диалога добавления, синхронизации и удаления.

Дизайн: тёмная тема, Manrope с кириллицей, сетка карточек, SVG-графики считаются
на сервере (детерминированные скриншоты, отсутствие скачков при загрузке).

Ключевое: **все числа форматируются по-русски** (неразрывные пробелы, запятая в
дробях) — иначе интерфейс читается как машинный дамп.

## Этап 5. Сервер и API

`src/server.mjs` — маршрутизация без фреймворка, JSON API, CSV, статика с белым
списком типов и MIME, CSP, защита от обхода каталога, лимит тела запроса.

`scripts/serve.mjs` — точка входа с корректной остановкой по сигналам.

## Этап 6. Тесты

| Уровень | Файл | Что проверяет |
| --- | --- | --- |
| Юнит | `tests/unit/metrics.test.mjs` | определения метрик, границы, малые выборки |
| Юнит | `tests/unit/account-url.test.mjs` | разбор ссылок и ошибки ввода |
| Юнит | `tests/unit/html.test.mjs` | экранирование, XSS |
| API | `tests/api/api.test.mjs` | маршруты, коды ошибок, идемпотентность, CSV, безопасность |
| Вёрстка | `scripts/check-layout.mjs` | 4 разрешения × 4 страницы: прокрутка, h1, метки, контраст WCAG AA, цели нажатия |
| Браузер | `tests/e2e.mjs` | сценарии: добавление, синхронизация, удаление, работа без JS, CSP |

Тесты API работают на временной базе и свободном порту — не трогают рабочие
данные и не конфликтуют при параллельном запуске.

## Этап 7. Документация и приёмка

`docs/TZ.md` — требования и определения метрик. `README.md` — запуск.
`docs/screenshots/` — кадры «до» и «после» с манифестом содержимого.

## Порядок проверки

```bash
npm ci
npm test          # юнит + API
npm run test:e2e  # вёрстка, контраст, сценарии в браузере
npm start         # http://127.0.0.1:4180
```

## Что осталось за рамками версии 1.0

- Авторизация и разделение доступа: сервис рассчитан на доверенную сеть.
- Официальные API платформ: требуют регистрации приложения и OAuth.
- Планировщик фоновой синхронизации: сейчас синхронизация запускается вручную.
- Прогноз охвата: данных для честной модели пока мало.
- Локализация интерфейса: только русский.

Эти пункты — не забытые долги, а осознанно отложенные части: каждая требует
внешних условий (ключи, аккаунты, юридические соглашения) или отдельного
продуктового решения.
