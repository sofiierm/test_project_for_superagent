# Техническое задание: веб-сервис аналитики контента креаторов

Документ описывает, что делает сервис, как считаются метрики, откуда берутся
данные и где заканчиваются его возможности. Версия 1.0.

## 1. Задача

Креатор публикует ролики в Instagram, YouTube и TikTok и не понимает, что
работает: тема, формат, время выхода, длина. Платформенная статистика разрознена
по трём приложениям, показывает только просмотры и не отвечает на вопрос «почему
этот ролик собрал больше».

Нужен один веб-сервис, который собирает публичные ролики с заданных аккаунтов,
считает по ним метрики и разбирает содержание — темы, хештеги, приёмы подачи,
тональность — а затем формулирует выводы на естественном языке.

## 2. Пользователь и сценарии

Пользователь — креатор или небольшой SMM-отдел, который ведёт несколько
аккаунтов. Основные сценарии:

1. Добавить профиль по ссылке и увидеть его ролики и метрики.
2. Сравнить аккаунты между собой на общем обзоре.
3. Понять, какие темы и приёмы дают охват и вовлечённость.
4. Выбрать время публикации и проверить ритм.
5. Выгрузить данные в таблицу для отчёта.

Вне рамок версии 1.0: авторизация пользователей, платные тарифы, интеграция с
официальными API платформ, прогнозирование охвата, работа с рекламными
кабинетами, мультиязычный интерфейс (интерфейс только на русском).

## 3. Функциональные требования

### 3.1 Аккаунты

| Требование | Поведение |
| --- | --- |
| Добавление по ссылке | Принимается адрес профиля Instagram, YouTube, TikTok или `@ник` с явно выбранной платформой |
| Разбор ввода | Ссылка на публикацию/видео распознаётся отдельно; если в адресе есть автор, извлекается профиль, иначе возвращается понятная ошибка |
| Дубликаты | Повторное добавление того же профиля отклоняется с кодом `409` и ссылкой на существующий аккаунт |
| Кириллические ники | Допускаются (`youtube.com/@ТихийВлог`) |
| Синхронизация | Забирает последние `SYNC_LIMIT` роликов, обновляет метрики, пишет запись в историю синхронизаций |
| Идемпотентность | Повторная синхронизация не создаёт дубликатов: ролик идентифицируется парой (аккаунт, внешний id) |
| Удаление | Удаляет аккаунт вместе с роликами и снимками метрик (каскадно) |
| Ошибки | Ошибка источника сохраняется в аккаунте и показывается в интерфейсе; выдуманные данные не подставляются |

### 3.2 Ролики и метрики

По каждому ролику хранятся: идентификатор на платформе, ссылка, заголовок,
описание, хештеги, дата публикации, длительность, просмотры, лайки, комментарии,
репосты, сохранения.

Метрики (определения — в разделе 5): ER ролика, ER аккаунта, медиана и среднее,
охват к подписчикам, выбросы, динамика периода, ритм публикаций, лучшее время.

### 3.3 Анализ содержания

- **Темы** — основы значимых слов после отсечения стоп-слов; для каждой темы —
  число роликов, доля, средний охват, множитель охвата относительно среднего.
- **Хештеги** — частота и охват.
- **Приёмы подачи** — вопрос, призыв к действию, цифры, список, срочность, личный
  опыт. Сравнивается ER у роликов с приёмом и без.
- **Тональность** — словарная оценка позитив/нейтрально/негатив с пометкой
  ненадёжности на малой выборке.

### 3.4 Выводы

Правила формируют наблюдения с уровнем важности (`critical`, `warning`,
`opportunity`, `info`), текстом, пояснением и рекомендуемым действием. Правила:
просадка или рост охвата ≥ 25 %, ER против ориентира платформы, аномальный
выброс, пауза в публикациях, лучшее время, короткие ролики, зависимость от одного
ролика, слабый ролик.

Выводы описательные, не причинные. Каждый указывает, на каких данных основан.

### 3.5 Интерфейс

Страницы: обзор, список аккаунтов, аккаунт, список роликов, ролик, «Как это
работает», страница 404.

Требования: серверная отрисовка (работает без JavaScript), тёмная тема, адаптив
от 360 px, клавиатурная доступность, контраст не ниже WCAG AA, выгрузка CSV.

### 3.6 API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/accounts` | Список аккаунтов с агрегатами |
| POST | `/api/accounts` | Добавить аккаунт |
| DELETE | `/api/accounts/:id` | Удалить аккаунт |
| POST | `/api/accounts/:id/sync` | Синхронизировать |
| GET | `/api/accounts/:id/videos` | Ролики аккаунта |
| GET | `/api/accounts/:id/videos.csv` | Выгрузка аккаунта |
| GET | `/api/videos?platform=` | Ролики с фильтром |
| GET | `/api/videos.csv` | Общая выгрузка |
| GET | `/api/overview` | Сводка и выводы |
| GET | `/api/runs` | История синхронизаций |
| GET | `/api/health` | Состояние и статистика |

Ошибки возвращаются в JSON `{ error, hint?, code? }` с осмысленным HTTP-кодом.

## 4. Нефункциональные требования

| Свойство | Требование |
| --- | --- |
| Зависимости | Ноль runtime-зависимостей: только стандартная библиотека Node.js |
| Node.js | ≥ 22.5 (используется `node:sqlite`) |
| Хранилище | SQLite-файл в `data/`, вне git |
| Приватность | Тексты не отправляются во внешние сервисы; cookies и пароли не запрашиваются |
| Безопасность | Экранирование всего пользовательского текста, CSP, защита от обхода каталога, лимит тела запроса |
| Производительность | Страница со 100 роликами отрисовывается быстрее 200 мс на локальной машине |
| Устойчивость | Падение источника данных не роняет сервер; ошибка видна пользователю |
| Наблюдаемость | Журнал синхронизаций в базе, ошибки — в stderr |

## 5. Определения метрик

- **Вовлечённость** = лайки + комментарии + репосты + сохранения.
- **ER** = вовлечённость / просмотры × 100 %. При нулевых просмотрах — 0.
- **ER к подписчикам** = просмотры / подписчики × 100 % — насколько ролик выходит
  за пределы своей аудитории.
- **Медиана** используется там, где среднее искажается одним вирусным роликом.
- **Выброс** — правило Тьюки: значение выше Q3 + 1,5·IQR. Требуется не меньше
  пяти роликов, иначе выбросы не считаются.
- **Динамика периода** — сумма метрики за последние 30 дней против предыдущих 30.
  Если в предыдущем периоде нет данных, изменение не рассчитывается (`null`), а не
  показывается как «+100 %».
- **Ритм** — медианный интервал между публикациями; «пауза» фиксируется, если с
  последнего ролика прошло больше двух медианных интервалов.
- **Лучшее время** — средний ER по часам и дням недели в часовом поясе
  `APP_TIME_ZONE`; на выборке меньше трёх роликов помечается как ненадёжное.
- **Множитель темы** — средний охват роликов с темой / средний охват всех роликов.

### Ориентиры ER по платформам

Правила сравнивают ER аккаунта с ориентиром: Instagram — 4 %, YouTube — 2,5 %,
TikTok — 5 %. Это **не официальные данные платформ и не наше исследование**:
взята середина диапазонов, которые из года в год называют отраслевые
бенчмарк-отчёты (Instagram ≈ 3–6 %, YouTube ≈ 2–4 %, TikTok ≈ 4–8 %). Ориентир
нужен как грубая система координат, а не как истина: «ER 0,8 % при ориентире
4 %» — повод разобраться, «ER 6 %» — норма. Значения вынесены в
`ER_BENCHMARKS` в `src/analysis/metrics.mjs`, чтобы их можно было заменить
своими.

Часовой пояс обязателен: без него «вечерний прайм-тайм» уезжает на несколько
часов, и рекомендация становится вредной.

## 6. Источники данных

| Провайдер | Что делает | Когда используется |
| --- | --- | --- |
| `demo` | Детерминированная генерация роликов и метрик | Демонстрация, тесты, работа без сети |
| `ytdlp` | Публичные данные через `yt-dlp` | Реальные аккаунты при наличии сети |
| `auto` | Пробует `ytdlp`, при неудаче — `demo` | По умолчанию |

Демо-данные всегда помечены в интерфейсе как демонстрационные. Сервис не выдаёт
сгенерированные числа за статистику платформы.

## 7. Ограничения

1. **Доступность платформ.** Instagram и TikTok ограничивают автоматический
   доступ. Возможны ошибки «требуется вход», «слишком много запросов»,
   страница-заглушка вместо профиля. Сервис сообщает об этом и не подставляет
   выдуманные значения.
2. **Скрытые метрики.** Просмотры и сохранения у части платформ недоступны без
   авторизации; ER тогда считается по доступным метрикам, графики могут быть
   пустыми.
3. **Анализ текста словарный.** Темы и тональность определяются морфологией и
   словарём, а не языковой моделью. Это быстро и приватно, но грубее ML.
4. **Токенизация.** Эвристики рассчитаны на русский и английский; CJK-текст
   разбирается хуже.
5. **Корреляция, не причинность.** Выводы не доказывают влияние.
6. **Снимок, а не поток.** Метрики фиксируются на момент синхронизации.
7. **Малые выборки.** При нескольких роликах выводы о времени и тональности
   помечаются как ненадёжные.
8. **Один пользователь.** Авторизации нет: сервис рассчитан на локальный запуск
   или доверенную сеть.

- [x] Мебельный лендинг удалён из репозитория полностью.
- [x] Сервис запускается командой `npm start` на чистой машине с Node.js 22.
- [x] На пустой базе создаются демо-аккаунты, и все страницы открываются.
- [x] Добавление, синхронизация и удаление аккаунта работают через интерфейс.
- [x] Повторная синхронизация не создаёт дубликатов.
